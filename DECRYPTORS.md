## 1. Filemoon  — PoW + AES-256-GCM + ECDSA attest
The most complex. Flow: `embed/details → access/challenge → (ECDSA worker) access/attest → embed/captcha → PoW → captcha/verify → embed/playback → AES-GCM decryption`.

- **PoW hash**: custom ChaCha-style hash (NOT SHA256). Preimage = `nonce + ":" + counter`, search for `leadingZeroBits ≥ difficulty`.
- **Decryption**: AES-256-GCM (via CTR, no tag verification). The `version` field (1-20) selects 2 real `key_parts` at indices `[n, 31-n]` (the rest are decoys). Key = concat of the 2 parts.
- **attest**: ECDSA P-256 signature done by the Cloudflare worker `filemoon-attest.kurzmathis4.workers.dev`.
- **Embed headers**: `X-Embed-Origin` (bare host), `X-Embed-Referer`, `X-Embed-Parent` (original embed URL), `X-Captcha-Token` (the verifyToken).

| Module | Location | Status |
|---|---|---|
| **movix** | `filemoonExtractor` L1673 · `FileMoonDecryptor` L2008 · `_aesgcmDecrypt` L1956 · `solvePoW`/`solvePoWLocal` L287 | ✅ 100% local (pure-JS AES-GCM + base64); PoW via worker `/pow` + budgeted local fallback (2) |
| **nakanime** | `extractFilemoon` L724 · `_fmDecryptPlayback`/`_aesgcmDecrypt` L~775 · `_fmSolvePoW` · `_fmSelectParts` L741 | ✅ 100% local (v1.0.14), same as movix |

**Reference implementation**: movix `_aesgcmDecrypt` + `FileMoonDecryptor` (pure-JS AES-GCM validated 50/50 vs crypto.subtle). Worker `/pow` + `/attest`: `sora tester/filemoon-pow.worker.js`.

## 6. nakanime  — XOR-encrypted API (derived key)
All API responses (search, sources) are **XOR**ed.
- **Key (32 bytes)** generated by `genererCleSecrete(apiRoute)`: `u = "nkapiv1" + apiRoute`, then for `k` from 0 to 31: `m = Σ (m*31 + charCode + k) & 255`.
- Raw bytes recovered via `text()` + `charCodeAt` (`iso-8859-1` byte-identity encoding so the binary isn't corrupted on iOS).

| Module | Location |
|---|---|
| nakanime | `genererCleSecrete` L33 · fetch+XOR L67-120 |

## 🔗 Link extractors (by host)

Modular reference implementation: **nakanime** (`extractVidmoly`/`extractSibnet`/… L191-316).
